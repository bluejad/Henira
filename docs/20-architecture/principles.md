# 核心设计原则（九条）

> 原则分层说明：
> - **P7 / P8 是结构原则**——由 kernel / protocol 与目录布局承载，框架本体保证；
> - **P1 – P6 是语义原则**——由**官方默认插件**实现，并作为官方预设**默认装载**（D-010）。框架不禁止替换官方插件；替换者接管对应语义责任（文档声明，无守护套件）；
> - **P9 是红线**——任何实现（官方或社区）不得违反。
>
> 来源标注：`[dsh]` / `[zcode]` / `[opencode]` = 公开仓库调研吸收（file:line 均可公开对证）；`[用户]` = 项目所有者明确要求；闭源产品（如 Claude Code）仅行为层参考、不设标签。借鉴仅限公开来源（D-004 / D-047）。

---

## P1 事件溯源会话 = 唯一事实源 `[dsh]`（官方 session 插件实现）

追加式 typed `SessionEvent` 日志是会话的唯一持久化形态：

- 模型历史**从不单独存储**，由 `deriveMessages()` 从事件日志派生；
- 不变量：**模型可见 ⟺ 已落日志**——任何发给模型的请求都能从日志完整重建；
- 一份数据同时服务：回放、fork/分支、UI 渲染、审计、调试、（未来的）评测输入；
- 事件词表是**开放注册表**（校验器 map——最小 duck 接口 D-051，定义在 protocol；官方变体由 session 包用 zod 实现注册）：官方 session 插件注册基础变体，插件可注册新事件类型；消费端封闭处用 `assertNever` 收尾；
- 所有"客户端已知事件清单""schema 反查表"都从注册表**派生**，禁止手抄——凡是两处手抄的东西必然漂移（手抄清单曾导致新事件被静默丢弃）。

## P2 append-only + 发送投影（官方 session / compaction 插件实现）

- 本地历史**永不删改**；出网形状由纯函数 `projectForRequest` 现场拼接；
- 这一个决定同时解决：压缩可重试、事件下标永稳、UI 历史永全、多压缩标记共存；
- 任何降级（如压缩失败回落滑窗）**必须发事件可见**——静默回落等于功能不存在。

## P3 LLM StreamEvent 契约（契约在 protocol，官方 llm 插件实现）

- 统一事件流契约：**封闭判别联合**（新增变体 = 编译报错），配套 `assertNever`；
- 接口不变量写进注释并测试锁定：
  1. `tool_call` 的 `argsText` 恒为模型原始 JSON 文本（截断防线只在 loop 层写一次，两条传输路径通用）；
  2. `usage` 先于 `finish` 发出；
  3. `tool_call` 在流结束后集中发；
- 能力探测（contextWindow、systemPromptUpdate 等）是**模型配置的解析产物**——引擎内禁止厂商备表（P9-4）；模型参数字典 = models.dev，配置层同步、手写覆盖字典（D-040）；
- 官方默认适配器基于 Vercel AI SDK provider 层（决策 D-007）。

## P4 工具执行管线（官方 tools 插件实现）

- `defineTool({ name, inputSchema（裸 JSON Schema，D-044）, execute(args, ctx), isConcurrencySafe? })`；
- 管线五段：**`tools/pre-execute` waterfall（allow / deny / ask）→ execute（超时 + AbortController 竞速）→ `tools/post-execute` → 权威结果**；
- ToolResult 带 `__` 前缀**带外通道**：检查点路径、任务引用、图片附件等元数据由 loop 路由到引擎/呈现层，不进模型上下文语义；
- 只读工具标记 `isConcurrencySafe`，可并行执行；
- 双层防护：声明式可见性过滤（模型根本看不到不该看的工具）+ 执行时兜底校验（防幻觉调用）。

## P5 审批 fail-closed，挂起会话状态 `[dsh]`（官方 approval 插件实现，预设默认装载）

以下语义由**官方 approval 插件**实现并默认装载；框架允许替换它，替换者自担语义责任（D-010）：

- `requestPermission(): Promise<Decision>`；
- 判定词表：`allowed-once | rejected | cancelled | unavailable`——**缺失、异常、不合规的回答一律 `unavailable`，必须拒**；不存在"答案缺失即放行"；
- **凭据路径硬拒**在一切规则链之外，且工具围栏 + 引擎兜底双保险——凭据泄进模型上下文不可撤回，不存在可放行的理由；凭据清单由官方 approval 插件承担（D-012④，kernel 纯机制不承载业务策略）；灾难性操作硬拒与凭据同列链外（D-039）；
- 每次 ask / decide 落**审计事件对**（`approval/asked` + `approval/decided`）；
- 审批状态属于**会话**而非连接：断线、刷新、多窗口都能重放同一张审批卡。

## P6 Loop 状态机 + 成套中断纪律（官方 loop 插件实现，预设默认装载）

以下纪律由**官方 loop 插件**实现并用测试锁定；同理允许替换、责任随替换转移：

- turn / step 两级状态机；inbox 唯一投递 = 排队持久化 + 条目"立即发送"插话（step 边界进场，D-045）；per-phase AbortController；
- **中断纪律全家桶**（五点缺一不可）：
  1. 掐流后先查 `aborted` 再诊断错误（防"干净收尾"被误判 retryable 触发重发）；
  2. 清 dangling `tool_calls`（防下次请求 400）；
  3. 工具执行与信号**竞速**，中断时合成结果走正常结算通路（不留"运行中"残影）；
  4. inflight 事件兜底补发；
  5. 错误落盘为事件（报错的回合也要有收尾）；
- **流式增量在 loop 层合并**：16ms 同类攒批——增量逐层全链穿透会饿死事件循环（攒批窗口 = 一帧，这是 UI 工程的通行做法）；
- loop **不内置产品"模式"**（ask/plan/build 之类），只暴露策略缝：工具过滤 + 提示注入 + waterfall/bail 钩子（P9 红线 2）。

## P7 机制内核 = 唯一内核（承重墙）`[dsh 精简版]`

- kernel 只提供**机制**：服务槽位 + `inject` 依赖排序 + **4 种事件模式**（`emit` / `serial` / `waterfall` / `bail`）+ **可逆卸载**（注册同步撤销、`stop()` 异步收尾）；装配 API：`createHarness().use(...)`（D-011）；
- `bail` 语义显式成文：顺序执行 listener，谁返回反对即停，总线返回 `Veto = { by, reason, resume? }`（`resume` 携带续跑提示，无反对返回 `undefined`）——真实用户是**官方熔断插件**：在 `loop/turn-stopping` 否决回合结束并注入续跑提示（D-013⑤）。dsh 用 serial + 持久化 inbox 注入实现同一效果，我们不采用那套实现；bail 是我们的设计选择；
- **kernel 不知道任何具体业务接口**——槽位接口（LoopService / ApprovalService 等）与事件词表全部在 protocol（D-012②）；
- 体量目标 **< 1000 行**；**不做** fiber / scope / HMR / 动态加载 / 配置文件概念（嵌入式场景可零配置使用）。

## P8 一切皆插件（含官方语义包）`[用户 + dsh]`

- **能插件实现的就插件处理，没有例外**：官方插件共 **21 个**（语义 5：会话 / 模型适配 / 工具 / 审批 / 循环；能力 11 按族分包：fs 服务 + fs-tools / fs-search、shell 服务 + shell-tools、fetch、压缩、子智能体、任务服务 + plan / todo（D-049）；读者 4：技能 / MCP / 钩子 / 命令；界面 1：官方默认界面套件 `plugin-web-ui`（D-043，M3 随 web 诞生）——清单以 [packages.md](./packages.md) 为准，不在此手抄，P9-5）；它们与社区插件走**同一条注册路径、同权、无特权 API**（D-018）——**官方工具件自己也只是服务消费者**（能力一律服务、跨包共享必经服务，D-049）；
- 插件**能增能换**：任何官方插件可被第三方实现整包替换——包括 loop 与 approval 本身（D-010）；
- 插件能力四件事：**注册工具 / 注册事件类型 / 挂事件钩子 / 占据并实现槽位**——仅此四件，不做更多（扩展面收敛）。界面挂载（`ctx.registerSlot`）与 `ctx.host` 门面（D-028）是宿主提供的 UI 模块契约，不属于内核扩展面（D-021）；
- 语义责任规则：**官方默认 = 安全默认**；替换官方语义插件者接管语义责任（一句文档声明，无守护套件，D-010 配套取舍）；
- 目录即宣言：全部官方插件物理放在 `plugins/`，`packages/` 只留机制、契约与宿主（D-012③）。
- **protocol 最小化规则**（D-013③）：protocol 只放"两个插件必须达成一致的东西"——槽位接口、事件信封与词表、跨插件 DTO；不放便利类型、不放单插件内部类型、不放产品概念。新增 protocol 类型先回答"谁和谁必须一致？"，答不出就不进；
- **替换者责任清单**（D-013④）——替换官方语义插件者必须自行保证以下语义；这是"安全默认"的实质内容，不是建议：
  1. **session**：只追加；"模型可见 ⟺ 已落日志"；未知事件类型无 `ignorable` 必须拒读；fork 边界落标记；
  2. **loop**：turn / step 事件成对（含异常路径）；五条中断纪律；回合结束原因必须落 `turn/end`；
  3. **approval**：`Decision` 四值；缺失 / 异常 / 非法返回一律 `unavailable` 且必须拒；凭据硬拒先于一切规则与模式；审计对成对且在回合内；
  4. **tools**：每个 `tool/call` 必有 `tool/result`（含中止合成）；预执行拒绝单调（后注册不得放宽先注册的拒绝）；
  5. **llm**：`StreamEvent` 三不变量（`argsText` 恒原始 JSON、`usage` 先于 `finish`、`tool-call` 流末集中）；
  6. **通用**：不绕过 `InteractionService` 私自弹窗收答；密钥不进事件 / 日志 / 模型上下文；会话文件不依赖进程内状态（重启可恢复）。

## P9 框架红线（产品化包袱黑名单）

以下五条是同类产品踩过的常见病（Claude Code 的 plan 模式即红线 2 的活例子，dsh 的无模式内核是我们跟的反例），框架层**明令禁止**：

1. **UI 状态不进会话文件**——会话只存对话与引擎事实；界面布局、选择状态等是客户端自己的事；
2. **核心无内置"模式"系统**——ask/plan/build/full 之类的产品概念不进任何层；内核只提供工具过滤 + 提示注入钩子；
3. **核心零用户可见文案**——引擎只发结构化事件，措辞、语言、渲染全部由呈现层决定；
4. **引擎内禁止厂商备表**——contextWindow / maxTokens 必须来自模型配置解析，不允许 `if (provider === 'xxx')` 之类的硬编码；
5. **协议单一真源**——一切清单（事件类型表、schema 反查表、客户端已知类型表）从事件注册表派生，禁止两处手抄。
