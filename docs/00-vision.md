# 愿景与定位

## 一句话

Reins 是一个开源的 Agent Harness 框架：**把驾驭 AI Agent 必需的内核做扎实，其余一切交给插件。**

## 核心哲学（项目的存在理由）

**框架本体只做机制，其余一切皆插件——包括会话、工具、审批、循环本身。**

- 内核（kernel）只提供机制：服务槽位、依赖装配、事件总线（4 种模式）、可逆装卸；契约层（protocol）提供一切槽位接口与词表。
- **会话、工具、审批、循环是官方语义插件**，上下文压缩、子智能体、具体工具是官方能力插件——它们与社区插件走同一条注册路径、同权、无特权 API，**任何官方插件都可以被整包替换**（沙箱、评测等其余能力在发布后按 backlog 补）。
- 装配双轨：开发者用 TS API（`createHarness().use(...)`）与项目 `reins.config.ts`；最终用户在界面上点（落 `~/.reins/config/settings.json`，D-015）；无 YAML patch。

> 目的不是抢占无人占领的生态位，而是做我们自己的。
> ——2026-11-11 讨论定论。不围绕竞品空白做设计，按"什么是必须的"划分内核边界。

## 不做什么（负面清单）

- ❌ 不做面向最终用户的 coding agent 产品——官方 server / Web UI 是**框架的正式宿主与自举狗粮**（D-035 / D-038），不是卖点本体。
- ❌ 不做全家桶：评测、可观测、RAG、图编排等不进内核，也不强制捆绑。
- ❌ 不做某一家模型的壳：多 provider 是前提假设，不是宣传点。
- ❌ 不复制任何现有项目（OpenCode / pi / Mastra / dsh 都只是参考物）。

## 目标用户

想在 TypeScript / Node 上搭建**自己的** Agent（对外产品或内部系统）的开发者：

- 需要可靠的**会话持久化 / 回放 / 分支**，而不是内存里的消息数组；
- 需要**治理**（权限、审批、审计）而不只是能跑的 demo；
- 希望能力靠**插件组装**，而不是接受一个全家桶框架；
- 需要跨 provider，不接受被单一厂商 SDK 锁死。

## 目标平台与形态

- **Node.js ≥ 20**，ESM，TypeScript 全量。
- **纯 headless 可用**：SDK 是一等公民；Web UI 是正式宿主（D-038），CLI（黑窗口聊天）发布后补（D-018）。
- v1 首发范围：**SDK + Web UI**（D-018 修订 D-006；CLI 移出 v1）。
